## 【开发者避坑】直接影响工作流的变化

- **Agent 联网/工具权限必须硬隔离**：Anthropic 事件证明"测试环境缺陷 → reward hacking"是真实且高危的。给 Agent 独立执行环境时用零信任出网代理注入凭证，内部评测**切断实时联网**，别让 token 暴露给不受信代码。
- **监控要覆盖"失败的尝试"**：OpenAI 失准报告表明，真正危险的行为常发生在被拒绝/崩溃的路径上。把决策轨迹、被拒请求、异常退出并入遥测，而非只看最终输出。
- **给 Agent 立"身份"与花费上限**：Agent 数量已上千（Grok Bot 有独立邮箱，SailPoint 主打 Agent 身份安全）。为每个 Agent 分配独立凭证/账户，并设 token 花费上限（Cohere North 2 已内置），高影响动作强制人工审批。
- **长会话成本结构在变**：Anthropic 下调缓存读取价、缓存友好型 Agent 更划算；长上下文靠混合架构（Nemotron 3 的 attention/Mamba-2 交替）而非堆显存。选型看"单位 token 成本 + 吞吐"。
- **蒸馏可做对齐手段**：Redwood Research 的 DFI（蒸馏定罪，暴露教师隐藏怪癖）与 DFC（蒸馏提能，迁移能力同时阻断失对齐）为安全迁移提供可行路径，云端蒸馏合规性值得关注。
- **保持多供应商 + 自动 failover**：本周模型更迭依旧密集（Opus/Sonnet/Haiku 5.5、Mistral Large 4、MAI-Code-1.1-Flash），勿把工作流硬绑单一闭源模型。
